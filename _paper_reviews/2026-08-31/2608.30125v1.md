## 公理审查结果

### 一、对象公理 — ✅ 9/10
**依据**：论文对象清晰且自洽：面向 T+V2M（文本+视频到音乐）任务，同时给出明确任务定义（背景音乐需同时匹配视频并服从显式文本指令）、明确系统边界（10 秒纯器乐片段、48 kHz、无演唱、无长篇配乐与交互编辑——作者在 Limitations 中主动声明）与明确的评测维度（指令跟随、音画对齐、音频质量）。架构组成有具体数字：MiniCPM4-0.5B 语义 LM（24 层、hidden 896）、FSQ 瓶颈 dim 256、8 层 RITE、4 层 LocDiT（patch size 4、流匹配）、冻结 SongBloom VAE。
**Wiki 证据**：全文方法节与 Limitations 节；GitHub README 任务描述与论文一致。

### 二、识别公理 — ✅ 8/10
**依据**：论文将问题归因为两点——重建式目标无法惩罚指令违例、DAR 架构中静态跨模态条件的表示瓶颈——并用消融直接验证了所识别机制的作用：在 Table 3 组件消融中，基座架构 FAD 3.044 / FD 22.592 / Density 0.258，加入预训练后 FAD 2.538；仅加入 Conditioning Connection（无 RL）即把 FAD 降至 1.724、FD 10.199，相对预训练模型 FAD 下降约 32%；而"有 RL 无 CC"的组合 FAD 1.618 但 FD 恶化到 17.920，说明 CC 与 RL 是可分离且各司其职的贡献。这是"识别→验证"闭环，比单纯的假设陈述强。
**Wiki 证据**：Table 3 组件消融五行的完整数字链条。

### 三、独立性公理 — ⚠️ 6/10
**依据**：评测的正项：客观指标（FAD/FD/KL/IS/IB/Density/Coverage）+ Gemini 全模态评审 + 18 人 A/B 主观评测（win rates：对 Video-Robin 音质 70%、乐感 53%、音画对齐 69%、总体 65%；Fleiss κ=0.249、Krippendorff α=0.245）三种独立证据源并存，且报告了一致性系数。扣分项：(1) 评测循环性——Gemini-2.5-Flash 既用于第 4/5 阶段训练数据生成（属性 prompt、每视频 4 条指令），又作为第 5 阶段奖励与最终 Gemini 全模态评审，评审方与训练信号同源；(2) ImageBind 未在音乐上训练却被用作音画对齐代理指标，作者自己承认这一点；(3) 风格/情绪奖励完全依赖 CMI-RM，其偏差会传播进最终模型。这些独立性缺口作者有部分自省（Limitations 列出后两条），但第一点循环性未被讨论。
**Wiki 证据**：五阶段课程（Gemini 抽取 prompt）+ Table 4 Gemini judge + Table 5 人类评测与 κ/α 系数。

### 四、压缩公理 — ⚠️ 7/10
**依据**：模型设计上有明确的压缩意识：FSQ 瓶颈 dim 256 压缩语义 LM 的规划表征，Conditioning Connection 用一个 W ∈ ℝ^(1024×896) 的加权线性组合把全部 24 层隐状态路由到每个 LocDiT 层（系数和为 1），以单一线性映射替代堆叠投影。文字表述紧凑，5 阶段课程、奖励分类（硬约束 tempo/key / 软约束 CMI-RM + Qwen2.5-Omni）、复合奖励 R = R_soft + r_tempo + r_key 各自一段讲清。扣分项：奖励设计的正反两面散落在正文与附录（Table 9/10/11/12），主实验指令跟随结果只在图 3 中给出无表格版；消融条件（"Preference opt. without CC"）的动机需要读者自行反推。
**Wiki 证据**：方法节 Conditioning Connection 公式与 FSQ/RITE 规格；附录消融表布局。

### 五、效用公理 — ⚠️ 7/10
**依据**：正向：可执行文本指令控制背景音乐是视频创作中的真实痛点，主观评测四项全胜且总体 win rate 65% 说明用户可感知的增益；hard-reward 路线让 tempo 精确跟随从 ~29.7 提到 32.0（Exact 命中）、Tempo MAE 从 2.7 降到 2.4，是可量化的可用性改进；IS 2.358、FD 10.128 为全部基线最佳。负向：仅支持 10 秒器乐、无演唱、无长篇结构，限制了实际商用场景；音色/流派表达受冻结 VAE 与冻结编码器限制；Qwen2.5-Omni 判题使第 5 阶段推理开销显著；失败案例显示 octave 等价错误仍在（150 BPM 目标生成 133.9；69.8 BPM 目标生成 133.9 仅在八度上等价），key 跟随也偏弱（Key Exact 仅 11.0 vs 10.1，几乎无区分）。
**Wiki 证据**：Table 2/5 主结果、指令跟随图 3 数值、Table 11 失败案例、Limitations 节。

### 六、新颖性公理 — ⚠️ 7/10
**依据**：两个贡献点的新颖度评估：(1) Conditioning Connection 是对"静态单一张量条件"的替代设计，逐层可学习加权的跨层条件路由在 V2M 文献中此前未见，但思想上接近已有条件融合技术（多层特征加权注入），属于中等增量的架构贡献，消融证明其有效性（FAD 降 32%）但机制解释停留在描述层面；(2) 音乐生成中的 reward 分类学（硬可验证约束 tempo/key 与软主观质量的组合 + DiffusionNFT 在线 RL + 防 reward-hacking 的速度场 KL 惩罚）是把 LLM 时代的 verifiable-reward RL 系统性引入音乐指令跟随，这部分相对新颖，V2M 基线（CMT、GVMGen、VidMuse、Video2Music、M2UGen）均无此能力，仅 Video-Robin 可比。整体系统的新颖性为"新组合 + 一个可验证的新组件"，非范式级创新。系统扩展自 VoxCPM（Apache 许可、已在 README 与 HF 标签中明确声明，无归属问题）。
**Wiki 证据**：方法节贡献声明、Table 2 中六个基线与 VIBE 的能力对比、Table 10 中 VMB（Gemini captioning + 纯文本条件）对照实验证明视觉信号有超出文本的增益（FAD 2.271、Density 0.0 vs VIBE 1.583/0.674）。

### 七、可复现公理 — ✅ 8/10
**依据**：开源信号完备（本次实测核验）：GitHub 仓库 Apache-2.0、目录结构覆盖训练配置/奖励模型/脚本/数据，HuggingFace 公开 checkpoint 与全部四个公开训练数据集（JamendoMaxCaps ~1.6M、MusicBench 52,768、CMI-Pref 3,527、V2M+HarmonySet 60K）；论文给出完整超参（AdamW lr 1e-4、LoRA r=8→64、β=0.5、group size 8、20 步推理）。扣分项：README 自述"路径硬编码到开发集群、无打包或安装器"，研究代码即原始运行代码，复现成本偏高；ReelBench 评测集的划分细节与第 5 阶段 8,000 视频的采样协议依赖内部流程；评审主观集（18 人）无法由读者直接重现。
**Wiki 证据**：gh api 实测 repo 元数据（created 2026-08-25、pushed 2026-09-01、size 138KB）；HF API 实测模型元数据；README INSTALL.md 指引。

## 总评

**优点**：这是一篇对象定义清楚、证据链完整的方法型论文。其一，它把"指令违例不惩罚"这一 V2M 领域的真实缺口转成了可验证的研究问题，并用组件消融证明了所提机制（Conditioning Connection）的独立贡献——单独加入即让 FAD 从 2.538 降到 1.724（约 32%）、FD 从 16.446 到 10.199。其二，把 verifiable reward（tempo 的八度等价处理、key 的 Circle-of-Fifths + Krumhansl-Schmuckler 双奖励）与主观奖励（CMI-RM + Qwen2.5-Omni）组合成完整的五阶段训练课程，是音乐指令跟随方向上少见的系统化 RL 方案，主结果上 IS 2.358、FD 10.128、Density 0.674、Coverage 0.610 全部领先，人类 A/B 评测总体 win rate 65% 且报告了 κ/α 一致性。其三，开源闭环（代码 + checkpoint + 四个公开数据集 + 带对比 demo 的项目页）在同类工作中质量偏上，并主动披露了失真风险与 AI 生成内容标注建议。

主要问题在于证据独立性与任务实用性两端。评测循环性未被正视：Gemini-2.5-Flash 同时承担训练数据合成、第 5 阶段奖励与最终全模态评审三个角色，"Gemini judge 上 5/6 轴领先"的结论因此有自证风险；ImageBind（未在音乐上训练）作为音画对齐代理指标、风格奖励完全寄生于 CMI-RM，进一步削弱了客观评测的独立性。指令跟随的关键指标提升幅度可疑地小：Key Exact 仅 11.0 vs 10.1（提升不足 1 个点），失败案例中 150 BPM 目标生成 133.9、69.8 BPM 目标生成 133.9 这类八度等价错误说明 hard reward 的设计对八度问题的处理只在奖励端生效、在生成端未解决。实用边界偏窄：10 秒纯器乐、无演唱、冻结 VAE 限制音色表达，且五阶段训练中最重的第 5 阶段依赖 Qwen2.5-Omni 判题，推理开销显著。此外 FAD/KL 相对 Video-Robin 有轻微回退（1.583 vs 1.511、1.3205 vs 1.2556），作者以"分布接近性与感知质量的 RL 权衡"解释，缺一份感知权衡的直接证据。本审稿未能通过 Semantic Scholar 与 OpenAlex 独立核验基线文献的引用与发表信息（两 API 均被限流/欠费拒绝），"已接收 EMNLP 2026 Findings" 亦仅为作者自述，此处如实记录。

## 日报摘要

- **Strength:** 提出 Conditioning Connection（逐层加权跨层条件路由，单独加入使 FAD 从 2.538 降至 1.724、约降 32%）与硬可验证奖励（tempo Exact 32.0、MAE 2.4，key Circle-of-Fifths + Krumhansl-Schmuckler）+ 软主观奖励的 5 阶段 RL 课程，主结果 FD 10.128、IS 2.358 全基线最佳，人类 A/B 总体 win rate 65%（18 人、7 模型、κ=0.249）。
- **Weakness:** 评测循环性未讨论（Gemini-2.5-Flash 同源承担训练数据、奖励与终评）、ImageBind 作音画代理、风格奖励寄生于 CMI-RM；指令跟随增益边际（Key Exact 11.0 vs 10.1）、八度等价错误仍在（150 BPM→133.9），且仅支持 10 秒器乐、无演唱。
